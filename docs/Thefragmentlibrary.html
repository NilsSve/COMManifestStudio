  1. Using the program

The fragment library

A fragment file holds the manifest text for one COM component in one version. COM Manifest Studio keeps them in a folder of your own, the Manifest Fragment Library (you choose the folder in Settings). There is also a global library on GitHub, in the ManifestFragmentsLibrary folder of the COM Manifest Studio repository, which all users of the program share.

Get new files from GitHub

Fragments > Get new files from GitHub... compares your library with the global one and lists the files that are new to you, and the ones that differ from your copy. Tick the ones you want and click Download Now!.

Create a fragment file

When no fragment file exists for a component, you can make one: Fragments > Create a fragment file.... Choose the component's file (.ocx or .dll) and click Create!. The component must be registered with Windows while the file is made, because the information is read from the registry; the dialog shows whether it is, and has Register! and Unregister! buttons. The fragment file gets the component file's name with ".txt" instead of ".ocx" or ".dll".

Create fragment files for a whole folder

Fragments > Create for a whole folder... makes fragment files for all the components (.ocx files) in a folder in one go - for a new Codejock release, for example. The list shows each component, whether it is registered, whether a fragment file already exists, and the result. A component marked "shared" uses the same class IDs as another file in the folder, which is the one registered: Codejock's ANSI, Unicode and x64 files do that. Existing fragment files are only replaced when you tick Replace fragment files that already exist.

Share your files on GitHub

If you made fragment files that the global library does not have, please share them: Fragments > Share your files on GitHub.... Two windows open - your library in Windows Explorer, and GitHub's upload page in your web browser. Drag the new files onto the upload page. GitHub turns an upload from someone without write access into a pull request, so each file is checked before it is added to the library. If you have no GitHub account, you can send the files by e-mail instead.
