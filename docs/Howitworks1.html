  1. Using the program

The five steps

The main window shows a program's manifest as five steps. Each step says what is done, and the next step to take is framed in amber, so you can always see what comes next.

1. Components

The fragment files of the COM components the program uses - one for each component. Add files... chooses them from your fragment library; you can also drag them from Windows Explorer onto the list. The list below the steps shows them, and the line above it says whether the selected file's component is registered with Windows. A new manifest must be saved (Save) before files can be added.

2. Build manifest

Build writes the components into the manifest file. Before anything is written, COM Manifest Studio checks that:

  • every fragment file is in your library,
  • no two fragment files declare the same COM classes - usually the 32-bit and the 64-bit file of one component, of which the program can use only one (see Duplicate type libraries),
  • the fragment files are for the program's platform (64-bit programs).

The part of the manifest that is not about COM components is kept as it is; the COM components in it are replaced by the ones you chose. The previous file is kept as a backup, with the date and time in its name, and Microsoft's mt.exe checks the new one. View opens the manifest file in the editor.

3. Copy COM files

Copy COM files checks that each component's file is in the program's folder, and copies the missing ones. COM Manifest Studio looks for a file in this order:

  1. your Common COM Library folder (Settings),
  2. the Codejock installation folder under Program Files, for a Codejock component,
  3. the folder the Windows registry names for the component - it asks before copying from there.

A fragment file can also name files the component needs (its dependencies); they are copied as well.

When a file is missing, the list shows it ticked, in red when COM Manifest Studio cannot find it to copy; Copy Components copies the ticked ones.

4. Embed, compress (optional)

The step reads the program file and says what it carries: no manifest of its own (then Windows reads the manifest file beside it), DataFlex's basic manifest without COM components, the same manifest as the file, or a different one. A program that has a manifest of its own is always run with that one - Windows does not look at the manifest file then.

  • Embed puts the manifest into the finished .exe with mt.exe. Compiling the program does the same thing in a better way, if its project settings embed the manifest - see When an antivirus program blocks Embed.
  • Compress makes the .exe file smaller, often by about 80%. Do it last, after the manifest is in the program, and before the program is signed. A program built with DataFlex 26 has Windows' Control Flow Guard protection; it can only be compressed if that protection is removed, and COM Manifest Studio asks before it does that. Compressed programs are also flagged more often by virus scanners.

5. Test run

  • Compile compiles the program with the DataFlex version its workspace is for - the program's source must be in the AppSrc folder beside the manifest. This is also how the manifest gets into the program when its project settings embed it.
  • Run starts the program, so you can check that it runs and that its controls appear.

Windows remembers a program's manifest for a while; if a change does not seem to take effect, see How Windows caches manifests.
